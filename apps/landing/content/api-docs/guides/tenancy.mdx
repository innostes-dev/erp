The innostes ERP API is architected around strict multi-tenant isolation. All domain records, module installations, and plugin configurations belong to a tenant organization.

## The `X-Tenant-ID` header

When an authenticated user belongs to multiple organizations, or an administrative caller performs tenant-scoped operations, the request specifies the active tenant using the `X-Tenant-ID` HTTP header:

```http
X-Tenant-ID: 1
```

### When the header is required

| Endpoint Category | `X-Tenant-ID` Required? | Resolution Behaviour |
| --- | --- | --- |
| **Global Operations** (e.g. `GET /tenants`, `POST /tenants`, `GET /auth/me`) | **Optional** | Operates at the platform administration tier. |
| **Tenant Operations** (e.g. `GET /tenants/current/modules`) | **Context Header** | The `X-Tenant-ID` header scopes module and plugin queries to the active tenant. |
| **Domain Operations** (e.g. CRM contacts, HRMS employee rosters) | **Required** | Scopes all database queries to the given tenant ID. |

---

## Scoping resolution logic

The server evaluates tenant context using the following precedence:

1. **Explicit path parameter**: If the endpoint URL contains `{tenant_id}`, the path argument overrides all headers.
2. **Explicit `X-Tenant-ID` header**: The integer value in the `X-Tenant-ID` header is parsed and validated against the caller's authorized tenant memberships.
3. **Primary user tenant**: If no header is provided and the caller is not an administrator, the user's default registered tenant is selected.

*Verified by contract test*: `apps/api-server/tests/test_behaviour_facts.py::test_x_tenant_id__scopes_request_to_explicit_tenant`.

## Error handling for tenancy

When tenant scoping checks fail, the API returns structured error responses:

### 1. Invalid tenant format (`422 Unprocessable Content`)
The header value must be an unsigned 64-bit integer. Passing non-numeric characters returns:

```json
{
  "detail": [
    {
      "loc": ["header", "x-tenant-id"],
      "msg": "Input should be a valid integer, unable to parse string as an integer",
      "type": "int_parsing"
    }
  ]
}
```

### 2. Tenant not found (`404 Not Found`)
If the requested tenant does not exist or has been hard-deleted:

```json
{
  "code": "TENANT_NOT_FOUND",
  "detail": "Tenant with id 99999 was not found",
  "status": 404
}
```

### 3. Non-member tenant access (`403 Forbidden`)
If a caller attempts to pass an `X-Tenant-ID` for an organization they are not a member of, access is denied:

```json
{
  "code": "PERMISSION_DENIED",
  "detail": "You do not have access to tenant 42",
  "status": 403
}
```

## Tenant lifecycle operations

Organizations can be managed through the [Tenancy endpoints](/api-reference/tenancy/list-tenants):

<Tabs items={["cURL", "TypeScript (fetch)", "Python (httpx)"]}>
  <Tab value="cURL">

```bash
# Query modules active for Northwind Traders
curl -X GET "http://localhost:8001/tenants/current/modules" \
  -H "Authorization: Bearer <your-access-token>" \
  -H "X-Tenant-ID: 3f2b1c9e-4d5a-6b7c-8e9f-0a1b2c3d4e5f"
```

  </Tab>
  <Tab value="TypeScript (fetch)">

```ts
const res = await fetch('http://localhost:8001/tenants/current/modules', {
  headers: {
    Authorization: `Bearer ${token}`,
    'X-Tenant-ID': '3f2b1c9e-4d5a-6b7c-8e9f-0a1b2c3d4e5f',
  },
});
const modules = await res.json();
console.log(modules);
```

  </Tab>
  <Tab value="Python (httpx)">

```python
import httpx

res = httpx.get(
    "http://localhost:8001/tenants/current/modules",
    headers={
        "Authorization": f"Bearer {token}",
        "X-Tenant-ID": "3f2b1c9e-4d5a-6b7c-8e9f-0a1b2c3d4e5f",
    },
)
print(res.json())
```
