# Accessibility

innostes UI components conform to the Web Content Accessibility Guidelines (WCAG) 2.2 Level AA standard. Designed for enterprise ERP and back-office applications at Northwind Traders Pvt Ltd, every primitive is engineered so that operators relying on screen readers, keyboard navigation, or high-contrast display modes complete tasks without friction.

## Standards and conformance

The component library targets WCAG 2.2 AA conformance across four core principles:

- **Perceivable**: Text contrast ratios meet or exceed 4.5:1 for normal text and 3:1 for large text and non-text user interface components. Visual state indicators are never conveyed solely through colour.
- **Operable**: All interactive elements are fully operable through the keyboard. Focus order preserves logical reading sequence, and modal containers trap keyboard focus whilst active.
- **Understandable**: Form inputs require explicit labelling, contextual error descriptions link programmatically via `aria-describedby`, and validation failures announce dynamically via ARIA live regions.
- **Resilient**: Markup relies on semantic HTML and WAI-ARIA 1.2 authoring patterns, ensuring compatibility across desktop browsers and assistive tools.

## Keyboard interaction model

Components follow standard WAI-ARIA design patterns:

- `Tab` and `Shift + Tab` navigate between interactive component boundaries.
- Arrow keys manage roving tabindex within composite controls such as menus, tabs, radio groups, and tree views.
- `Escape` dismisses floating overlays, popovers, context menus, and dialogs, restoring focus to the triggering element.
- `Space` and `Enter` activate buttons and toggle selection states.

## Testing and verification

Accessibility is verified through automated and manual testing pipelines:

1. **Automated audits**: Axe-core and Vitest DOM testing run on every commit to detect missing ARIA attributes, invalid roles, and landmark omissions.
2. **Keyboard audits**: Full focus-trap, tab order, and shortcut verifications run across composite widgets.
3. **Screen reader verification**: Manual testing with NVDA on Windows and VoiceOver on macOS across Chrome, Firefox, and Safari.
