## When to use

Use `toast` to communicate transient outcomes of user-initiated operations without interrupting workflow:

- Confirming successful record creation, deletion, or archival ("PO-8410 created").
- Providing short-lived "Undo" buttons after bulk batch actions.
- Tracking asynchronous background mutations via `toast.promise`.

When deciding between feedback mechanisms:
- Use `toast` for transient, non-critical confirmations that do not require explicit operator acknowledgement.
- Use [Alert](/ui/docs/components/feedback/alert) for persistent warnings that remain in the page flow until resolved.
- Use [Alert Dialog](/ui/docs/components/overlays/alert-dialog) for high-stakes, irreversible confirmations.
- Refer to the [Feedback decision guide](/ui/docs/components/feedback#feedback-decision-guide) for full guidance.

## Examples

### Toaster configuration

Mount `<Toaster />` once near the root of your application (typically in `layout.tsx` or `App.tsx`):

```tsx
import { Toaster } from '@innostes/ui';

export function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Toaster position="bottom-right" />
      </body>
    </html>
  );
}
```

### Toast triggers and shortcuts

Call `toast` imperatively from anywhere in your codebase—including asynchronous handlers, store callbacks, or API clients:

```tsx
import { toast } from '@innostes/ui';

// Direct notification
toast('Draft saved automatically');

// Semantic shortcuts
toast.success('Invoice INV-8402 generated');
toast.info('Export queue is processing 42 records');
toast.warning('Warehouse quota exceeds 90%');
toast.error('Failed to sync GSTN data', {
  description: 'Network gateway timed out. Please retry shortly.',
});
```

### Action buttons and undo patterns

Attach an interactive action button to the toast notification by passing the `action` property:

```tsx
import { toast } from '@innostes/ui';

export function archivePurchaseOrder(id: string) {
  // Archive mutation logic...

  toast('Purchase order archived', {
    action: {
      label: 'Undo',
      onClick: () => restorePurchaseOrder(id),
    },
    timeout: 6000,
  });
}
```

### Async promise tracking

Use `toast.promise` to automatically transition a toast through loading, success, and error states as an asynchronous promise resolves:

```tsx
import { toast } from '@innostes/ui';

async function handleSubmitQuotation(quotationData: FormData) {
  await toast.promise(
    fetch('/api/v1/quotations', { method: 'POST', body: quotationData }),
    {
      loading: 'Submitting quotation to procurement portal…',
      success: 'Quotation submitted successfully.',
      error: (err) => `Failed to submit: ${(err as Error).message}`,
    }
  );
}
```

### Updating and dismiss controls

Every toast call returns a unique string identifier. Use `toast.update` to modify an active toast or `toast.dismiss` to close it programmatically:

```tsx
import { toast } from '@innostes/ui';

const toastId = toast.loading('Exporting ledger CSV…');

try {
  await exportLedger();
  toast.update(toastId, {
    type: 'success',
    title: 'Ledger export complete',
    timeout: 4000,
  });
} catch {
  toast.update(toastId, {
    type: 'error',
    title: 'Export interrupted',
    timeout: 5000,
  });
}
```

## Accessibility

`Toast` is built on Base UI Toast primitives (`@base-ui/react/toast`).

### Politeness and ARIA live regions

- Standard notifications (`default`, `info`, `success`) use `priority="low"`, emitting `aria-live="polite"`. The screen reader announces the notification when the user pauses their current interaction.
- Errors (`type="error"`) automatically set `priority="high"`, emitting `aria-live="assertive"`. The screen reader announces error notifications immediately, ensuring operators are alerted to failures.
- Hovering or shifting keyboard focus to the toaster pauses the auto-dismiss timer, allowing users sufficient time to read messages or click actions.

### Focus management and dismiss actions

- Toasts include an accessible close button (`aria-label="Close"`) with keyboard accessibility.
- When an `action` button is present, operators can press `Tab` into the toast region to trigger it without losing their previous document position.

### Imperative toast methods

| Method | Signature | Description |
| --- | --- | --- |
| `toast` | `(title, options?) => string` | Dispatches a default toast notification. |
| `toast.success` | `(title, options?) => string` | Dispatches a success toast with checkmark icon. |
| `toast.error` | `(title, options?) => string` | Dispatches an assertive error toast. |
| `toast.warning` | `(title, options?) => string` | Dispatches a warning toast with alert triangle. |
| `toast.info` | `(title, options?) => string` | Dispatches an informational toast. |
| `toast.loading` | `(title, options?) => string` | Dispatches a persistent loading toast with spinner. |
| `toast.update` | `(id, options) => void` | Updates an existing toast's title, description, or type. |
| `toast.dismiss` | `(id?) => void` | Closes a specific toast, or all toasts when called without ID. |
| `toast.promise` | `(promise, messages) => Promise<T>` | Binds toast status to a Promise's lifecycle. |
