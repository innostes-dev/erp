Buttons allow users to execute single-tap operations, submit forms, confirm transactions, and trigger dialogues. Built on Base UI's button primitive, `@innostes/ui` buttons guarantee visible keyboard focus rings, proper disabled state semantics, and render polymorphism without invalid DOM nesting.

<ComponentPreview name="actions/button/basic" />

## Import

```tsx
import { Button, buttonVariants } from '@innostes/ui';
```

## When to use

- **Use Button** for operational actions such as saving records, approving purchase orders, opening modals, or deleting items.
- **Use Link or Button with `render`** when navigating to a new URL or page route.
- **Use ButtonGroup** when grouping closely related actions into a single segmented bar (e.g. Save, Save and submit).
- **Use Toggle or ToggleGroup** when switching a two-state option on or off, or selecting from a mutual exclusion set.

### Screen readers and ARIA

- **Native `<button>` element**: Guarantees standard button accessibility semantics in the accessibility tree.
- **Icon-only requirement**: When `iconOnly` is enabled, an accessible name **must** be provided via `aria-label`.
- **Loading state**: When `loading={true}` is set, the button receives `aria-busy="true"` and `disabled={true}`, preventing duplicate network invocations.

## Guidelines

<DoDont>
  <Do>
    Use descriptive, action-oriented verbs such as "Approve purchase order", "Save changes", or "Void invoice".
  </Do>
  <Dont>
    Never use vague labels such as "Click here", "Submit", or "OK" on enterprise action buttons.
  </Dont>
</DoDont>

<DoDont>
  <Do>
    Always supply an `aria-label` when using the `iconOnly` prop so screen readers describe the operation.
  </Do>
  <Dont>
    Never leave icon-only buttons unlabelled, or use decorative icons that duplicate neighbouring text labels.
  </Dont>
</DoDont>
