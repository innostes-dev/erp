`Switch` provides a physical toggle slider for binary configuration options. Built on Base UI's switch primitive, it emits `role="switch"` semantics and smooth CSS sliding transitions. It is designed for preferences and live operational flags (e.g. enabling automatic replenishment) where changes activate immediately without a manual save step.

<ComponentPreview name="forms/switch/basic" />

## Import

```tsx
import { Switch } from '@innostes/ui';
```

## When to use

- **Use Switch** for standalone configuration toggles that apply immediately (e.g. "Dark mode", "SMS dispatch alerts").
- **Use Checkbox** for form fields where selections require an explicit "Submit" button, or when multi-item table selection is required.
- **Use Toggle** for styling buttons inside rich text toolbars or view filters.

### Inside a field with description

Pair the switch with a clear label and operational explanation:

```tsx
<Field>
  <label className="flex items-start gap-3 cursor-pointer">
    <Switch name="autoReorder" defaultChecked className="mt-0.5" />
    <div>
      <span className="text-sm font-medium text-foreground">
        Automated replenishment
      </span>
      <p className="text-xs text-muted-foreground">
        Automatically draft purchase orders when inventory falls below minimum buffer.
      </p>
    </div>
  </label>
</Field>
```

### Sizes

Switches are available in `sm` and `md` (default) sizes:

```tsx
<Switch size="sm" aria-label="Compact switch" />
<Switch size="md" aria-label="Default switch" />
```

### Screen readers and ARIA

- **`role="switch"`**: Emitted automatically to ensure assistive technologies announce "switch, on" or "switch, off" rather than generic checkboxes.
- **`aria-checked`**: Synchronized dynamically with the active state.
- **Required labelling**: Ensure the switch is enclosed within a `<label>` or provided an explicit `aria-label`.

## Guidelines

<DoDont>
  <Do>
    Use `Switch` when toggling the setting takes immediate effect in the system.
  </Do>
  <Dont>
    Never use `Switch` in standard forms where the user must still click an external "Save" or "Submit" button; use `Checkbox` instead.
  </Dont>
</DoDont>

<DoDont>
  <Do>
    Pair the switch with clear textual labels that explain what feature is enabled when turned on.
  </Do>
  <Dont>
    Never change the label text based on state (e.g. changing "Off" to "On"); keep the label static.
  </Dont>
</DoDont>
