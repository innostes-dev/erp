## When to use

Use `KanbanBoard` when managing visual work pipelines where records transition across discrete sequential stages:

- **Purchase order approvals**: Draft → Verification → Manager Review → Authorized.
- **Logistics consignment pipeline**: Booked → Packed → Dispatched → In Transit → Delivered.
- **Vendor KYC onboarding**: Applied → Documents Submitted → Bank Verification → Approved.

**Do not use KanbanBoard for:**
- Standard multi-column tabular data with sorting and filtering — use [DataTable](/ui/docs/components/data-display/data-table).
- Linear step-by-step form wizards — use [Stepper](/ui/docs/components/navigation/stepper).
- Flat chronological event streams — use [ActivityFeed](/ui/docs/widgets/activity-feed).

## Examples

### The move contract and optimistic updates

`onValueChange` fires when a card is dropped or moved via keyboard, providing the next column array and a `KanbanMove` descriptor:

```tsx
'use client';

import { useState } from 'react';
import { KanbanBoard, moveKanbanItem, type KanbanColumn, type KanbanMove, toast } from '@innostes/ui';

export function ProcurementPipeline({ initialColumns }: { initialColumns: KanbanColumn<Order>[] }) {
  const [columns, setColumns] = useState(initialColumns);

  const handleMove = async (nextColumns: KanbanColumn<Order>[], move: KanbanMove) => {
    // 1. Optimistically apply change to local state immediately
    const previousColumns = columns;
    setColumns(nextColumns);

    try {
      // 2. Persist to API
      const response = await fetch(`/api/orders/${move.itemId}/stage`, {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          toStage: move.toColumnId,
          toIndex: move.toIndex,
        }),
      });

      if (!response.ok) throw new Error('Stage transition rejected by server');
      toast.success('Purchase order moved');
    } catch (err) {
      // 3. Rollback immediately on server failure
      setColumns(previousColumns);
      toast.error('Failed to update stage. Reverting position.');
    }
  };

  return (
    <KanbanBoard
      aria-label="Procurement pipeline"
      value={columns}
      onValueChange={handleMove}
      canMove={(move) => {
        // Enforce stage constraints: cannot jump directly from Draft to Authorized
        if (move.fromColumnId === 'draft' && move.toColumnId === 'authorized') {
          toast.warning('Draft orders must undergo verification before authorization.');
          return false;
        }
        return true;
      }}
      getItemLabel={(order) => `${order.id} · ${order.supplier}`}
      renderCard={(order) => <OrderCard order={order} />}
      onCardOpen={(order) => router.push(`/purchases/${order.id}`)}
    />
  );
}
```

### Column WIP limits

Set `limit={5}` on a column to enforce Work In Progress (WIP) bounds. The column header automatically renders a badge showing `count / limit` and turns warning/destructive when capacity is exceeded:

```tsx
const columns: KanbanColumn<Order>[] = [
  { id: 'review', title: 'Under review', limit: 4, items: reviewOrders },
  { id: 'dispatched', title: 'Dispatched', limit: 8, items: dispatchedOrders },
];
```

### Touch devices and mobile strategy

On mobile touch devices where native HTML drag-and-drop is limited, `KanbanBoard` provides a built-in touch column selector, allowing users to tap a card and pick its destination column directly from a native select control, or trigger `onCardOpen` to update the stage from an inspection drawer.

## Accessibility

`KanbanBoard` provides complete non-pointer keyboard operation and screen reader announcements.

### ARIA attributes

- Columns render as semantic `<section>` regions with `aria-labelledby` referencing column titles.
- Cards maintain `role="button"` or `role="article"` with clear `aria-roledescription="Draggable card"`.
- Live region announcements notify screen readers when a card is grabbed, moved, dropped, or blocked by `canMove`.
