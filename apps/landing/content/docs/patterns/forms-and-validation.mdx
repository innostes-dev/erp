Enterprise ERP forms handle sensitive fiscal calculations, statutory compliance (such as GSTIN and PAN verification), and multi-step workflows. This guide demonstrates how to build resilient, accessible forms using `@innostes/ui` form primitives paired with React Hook Form, Zod schema validation, and Next.js Server Actions.

## The problem

Form implementations in enterprise software frequently suffer from three critical flaws:
1. **Disconnected validation state**: Errors caught on the server fail to associate with the corresponding input DOM element, leaving screen reader operators stranded without accessible announcements.
2. **Loss of unsaved progress**: Operators accidentally navigate away from deep 20-field procurement forms, discarding unsubmitted input without warning.
3. **Overly aggressive validation**: Showing validation error messages before the operator has finished typing into an input field (poor input ergonomics).

## Recommended approach

- **Colocate schema definitions**: Define a single Zod schema shared between client validation and server action handlers.
- **Accessible form primitives**: Wrap each control in [`Field`](/ui/docs/components/forms/field) (`FieldLabel`, `FieldDescription`, `FieldError`) to guarantee automated `aria-invalid`, `aria-describedby`, and error ring associations.
- **Graceful validation triggers**: Validate on blur or submit rather than every keystroke (`mode: 'onTouched'`).
- **Confirmation dialogs**: Intercept window unload and router transitions with [`AlertDialog`](/ui/docs/components/overlays/alert-dialog) when forms are dirty.

## Complete example: Purchase order creation with React Hook Form & Zod

Below is a complete implementation of a purchase order form for Northwind Traders Pvt Ltd, including client schema validation and server action dispatch:

```tsx
'use client';

import { useState } from 'react';
import { useForm, Controller } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import {
  Field,
  FieldLabel,
  FieldDescription,
  FieldError,
  Input,
  Select,
  Textarea,
  Button,
  FormGrid,
  FormActions,
  toast,
  AlertDialog,
  AlertDialogTrigger,
  AlertDialogContent,
  AlertDialogHeader,
  AlertDialogTitle,
  AlertDialogDescription,
  AlertDialogFooter,
  AlertDialogClose,
} from '@innostes/ui';

// 1. Unified Zod validation schema
const purchaseOrderSchema = z.object({
  poNumber: z
    .string()
    .min(5, 'PO number must be at least 5 characters')
    .regex(/^PO-\d{4}-\d{3,4}$/, 'Must follow format PO-YYYY-NNN (e.g. PO-2026-081)'),
  vendorGstin: z
    .string()
    .regex(/^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}$/, 'Invalid 15-character Indian GSTIN format'),
  expectedAmount: z
    .number({ invalid_type_error: 'Amount is required' })
    .positive('Order value must be greater than zero'),
  deliveryNotes: z
    .string()
    .max(500, 'Notes cannot exceed 500 characters')
    .optional(),
});

type PurchaseOrderFormValues = z.infer<typeof purchaseOrderSchema>;

export function PurchaseOrderForm({ onSubmitAction }: { onSubmitAction: (data: PurchaseOrderFormValues) => Promise<{ success: boolean; serverErrors?: Record<string, string> }> }) {
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [discardDialogOpen, setDiscardDialogOpen] = useState(false);

  const {
    register,
    handleSubmit,
    setError,
    reset,
    formState: { errors, isDirty },
  } = useForm<PurchaseOrderFormValues>({
    resolver: zodResolver(purchaseOrderSchema),
    mode: 'onTouched',
    defaultValues: {
      poNumber: 'PO-2026-081',
      vendorGstin: '29ABCDE1234F1Z5',
      expectedAmount: 89400,
      deliveryNotes: '',
    },
  });

  const onFormSubmit = async (values: PurchaseOrderFormValues) => {
    setIsSubmitting(true);
    try {
      const result = await onSubmitAction(values);
      if (!result.success && result.serverErrors) {
        // Map server-side rejection keys to individual form fields
        for (const [field, message] of Object.entries(result.serverErrors)) {
          setError(field as keyof PurchaseOrderFormValues, { type: 'server', message });
        }
        toast.error('Submission failed. Check highlighted fields.');
      } else {
        toast.success(`Purchase order ${values.poNumber} created successfully`);
        reset(values); // clear dirty state
      }
    } catch {
      toast.error('Network failure communicating with procurement API.');
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit(onFormSubmit)} className="space-y-6">
      <FormGrid columns={2}>
        <Field invalid={Boolean(errors.poNumber)}>
          <FieldLabel htmlFor="poNumber">PO number</FieldLabel>
          <Input
            id="poNumber"
            {...register('poNumber')}
            disabled={isSubmitting}
            placeholder="PO-2026-081"
          />
          <FieldDescription>Standard Northwind fiscal identifier.</FieldDescription>
          {errors.poNumber && <FieldError>{errors.poNumber.message}</FieldError>}
        </Field>

        <Field invalid={Boolean(errors.vendorGstin)}>
          <FieldLabel htmlFor="vendorGstin">Vendor GSTIN</FieldLabel>
          <Input
            id="vendorGstin"
            {...register('vendorGstin')}
            disabled={isSubmitting}
            placeholder="29ABCDE1234F1Z5"
          />
          <FieldDescription>State code (29 Karnataka) followed by 10-digit PAN.</FieldDescription>
          {errors.vendorGstin && <FieldError>{errors.vendorGstin.message}</FieldError>}
        </Field>

        <Field invalid={Boolean(errors.expectedAmount)}>
          <FieldLabel htmlFor="expectedAmount">Order value (₹)</FieldLabel>
          <Input
            id="expectedAmount"
            type="number"
            {...register('expectedAmount', { valueAsNumber: true })}
            disabled={isSubmitting}
          />
          {errors.expectedAmount && <FieldError>{errors.expectedAmount.message}</FieldError>}
        </Field>

        <Field invalid={Boolean(errors.deliveryNotes)} className="col-span-full">
          <FieldLabel htmlFor="deliveryNotes">Consignment delivery instructions</FieldLabel>
          <Textarea
            id="deliveryNotes"
            {...register('deliveryNotes')}
            disabled={isSubmitting}
            placeholder="Specify unloading bay, forklift requirements, or contact person."
          />
          {errors.deliveryNotes && <FieldError>{errors.deliveryNotes.message}</FieldError>}
        </Field>
      </FormGrid>

      <FormActions align="between" sticky>
        {isDirty ? (
          <AlertDialog open={discardDialogOpen} onOpenChange={setDiscardDialogOpen}>
            <AlertDialogTrigger render={<Button variant="outline" type="button" />}>
              Cancel
            </AlertDialogTrigger>
            <AlertDialogContent>
              <AlertDialogHeader>
                <AlertDialogTitle>Discard unsaved changes?</AlertDialogTitle>
                <AlertDialogDescription>
                  You have modified procurement details. Leaving now will discard all unsaved edits.
                </AlertDialogDescription>
              </AlertDialogHeader>
              <AlertDialogFooter>
                <AlertDialogClose render={<Button variant="outline" />}>
                  Continue editing
                </AlertDialogClose>
                <AlertDialogClose
                  render={<Button variant="destructive" />}
                  onClick={() => reset()}
                >
                  Discard changes
                </AlertDialogClose>
              </AlertDialogFooter>
            </AlertDialogContent>
          </AlertDialog>
        ) : (
          <Button variant="outline" type="button" onClick={() => reset()}>
            Reset
          </Button>
        )}

        <Button type="submit" loading={isSubmitting}>
          Submit purchase order
        </Button>
      </FormActions>
    </form>
  );
}
```

## Next.js Server Action recipe

When dispatching form state directly to Server Actions, parse the payload against your Zod schema and return typed error maps rather than throwing unhandled exceptions:

```ts
// app/actions/procurement.ts
'use server';

import { z } from 'zod';

export async function createPurchaseOrderAction(formData: unknown) {
  const parseResult = purchaseOrderSchema.safeParse(formData);

  if (!parseResult.success) {
    const serverErrors: Record<string, string> = {};
    for (const issue of parseResult.error.issues) {
      const field = issue.path[0];
      if (field) serverErrors[String(field)] = issue.message;
    }
    return { success: false, serverErrors };
  }

  // Database transaction with Northwind ERP database
  const order = await db.orders.create({ data: parseResult.data });
  return { success: true, orderId: order.id };
}
```

## Multi-step forms with Stepper

For lengthy multi-stage funnels (e.g. 1. Supplier details → 2. Item specifications → 3. Tax and delivery → 4. Review):

1. **Maintain step index in local state**: `const [step, setStep] = useState(0)`.
2. **Validate only active step fields before progressing**: Trigger `trigger(['poNumber', 'vendorGstin'])` with React Hook Form to verify the active slice before incrementing `step`.
3. **Reflect progress with [`Stepper`](/ui/docs/components/navigation/stepper)**: Pass `steps` with `currentStep={step}`. Completed steps become clickable to permit backward revisions, while forward jumps remain locked until validation passes.

## Accessibility notes

- **Error association**: `Field` links `FieldError` with the input using `aria-describedby` automatically.
- **Focus first error**: Upon submit failure, immediately shift focus to the first invalid input element using `react-hook-form`'s automatic focus management.
- **Disabled state while saving**: Always mark inputs `disabled={isSubmitting}` to prevent duplicate clicks and double submissions.

## Common mistakes

| Anti-pattern | Recommended solution |
| :--- | :--- |
| Validating on every single keystroke (`mode: 'onChange'`). | Use `mode: 'onTouched'` or `mode: 'onBlur'` to avoid interrupting typing. |
| Using `window.alert()` or unformatted error banners. | Use inline `FieldError` directly under the affected field. |
| Allowing form dismissal while async submission is pending. | Disable close buttons and wrap actions with `loading={isSubmitting}`. |
| Hardcoding non-localized regex for Indian statutory identifiers. | Use verified GSTIN (15-character alphanumeric) and PAN (10-character) regex patterns. |
