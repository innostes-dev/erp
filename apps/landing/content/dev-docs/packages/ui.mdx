This page covers **working on** the package. For **using** it, see the
[innostes UI docs](/ui/docs). The full checklist for new components is in
`packages/ui/CONTRIBUTING.md`.

## Tasks

| Command | What it does |
| --- | --- |
| `pnpm nx build ui` | JS, types, `dist/styles.css` and `dist/api.json` |
| `pnpm nx test ui` | Unit tests (Vitest + Testing Library, jsdom) |
| `pnpm nx test ui --coverage` | Tests with a coverage report in `coverage/packages/ui` |
| `pnpm nx typecheck ui` | Type-check the library and the tests |
| `pnpm nx run-many -t test typecheck -p ui-react17-tests ui-react18-tests` | The same tests and a type check on React 17 and 18 |
| `pnpm nx release --dry-run` | Preview the next version and publish |

Each component lives in `src/components/<category>/<name>/<name>.tsx`, is re-exported by
`src/components/<category>/index.ts`, and every category is re-exported by `src/index.ts`.
Tests sit next to the code (`*.test.tsx`).

| Path | Purpose |
| --- | --- |
| `src/lib/cn.ts` | `clsx` + `tailwind-merge`, so a consumer's `className` wins |
| `src/lib/merge-class-name.ts` | The same for Base UI's state-function `className` |
| `src/lib/styles.ts` | Class strings shared by popups, list items and backdrops |
| `src/lib/icons.tsx` | Internal icons, so the package has no icon-library dependency |
| `tailwind/theme.css` | Design tokens as `@theme default`, so apps can override them |
| `tailwind/dark.css` | Opt-in dark theme, plain CSS variables |
| `scripts/generate-api-docs.mjs` | Reads TSDoc with `react-docgen-typescript` and writes `dist/api.json` |

## How the build works

1. Vite builds one file per source module (`preserveModules`). Files that start with `'use client'`
   keep it, so only interactive components become client modules.
2. `vite-plugin-dts` writes the type declarations.
3. The Tailwind CLI compiles `dist/styles.css` for apps without Tailwind.
4. `generate-api-docs.mjs` writes `dist/api.json`. The docs site renders every API table from it,
   so the docs always match the code.

`react`, `react-dom`, `@base-ui/react`, `clsx`, `tailwind-merge` and `class-variance-authority`
are never bundled.

## How the docs are built

| What | Where |
| --- | --- |
| Pages | `apps/landing/content/docs/components/<category>/<name>.mdx` |
| Live examples | `apps/landing/components/demos/<category>/<name>/<example>.tsx` |
| Examples registry | Generated by `apps/landing/scripts/generate-demo-registry.mjs` |

In MDX, `<ComponentPreview name="overlays/dialog/basic" />` renders the example and shows its
exact source, and `<ApiTable components={['DialogContent']} baseUi="dialog" />` renders the props
from `api.json`. Neither can go stale.

## React versions

The package supports **React 17, 18 and 19** (its `peerDependencies`), so apps can adopt it without
upgrading React first.

- Every component uses `forwardRef`; React 19's ref-as-prop isn't relied on.
- No React 18+ only APIs (`useId`, `useSyncExternalStore`, `useTransition`, …) in the package.
- `tests/ui-react17` and `tests/ui-react18` install that React version like a consumer app, and run
  the same component tests against the **built** package, plus a type check against that version's
  types. See `tests/README.md`.

## Testing

- Test what users observe: roles, accessible names, ARIA state, keyboard behaviour.
- Prefer `getByRole`, then `getByLabelText`, then `getByText`. Avoid class-name and snapshot tests.
- `src/test/setup.ts` adds jest-dom matchers and the browser APIs jsdom lacks.
