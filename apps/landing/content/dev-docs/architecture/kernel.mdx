The kernel is the platform foundation plug-in for innostes ERP. It provides two distinct layers of functionality:

1. **`core`**: Infrastructure and foundation utilities with **no dedicated tables**: configuration management, async database engine, authentication security primitives, the `BaseModule` contract, standard Pydantic schemas, and `BaseService` CRUD abstractions.
2. **Platform features**: Foundational multi-tenant capabilities required by all enterprise business modules:
   - **`setup`**: First-run system installation, token protection, and installation locking.
   - **`tenancy`**: Tenant lifecycle management, isolation context, and tenant settings.
   - **`user`**: Identity administration, user management, and role-based access control (RBAC).
   - **`auth`**: Authentication, rotating refresh token families, password reset, and API key management.

- **Shared API client**: Injects tenant context headers (`X-Tenant-ID`) and handles automatic token refreshing transparently.

## Layering Invariants

Within `kernel/backend`, subpackages obey strict one-way layering:

```text
core  ───►  tenancy  ───►  user  ───►  auth
```

Packages may only import from layers strictly to their left. The platform architecture fitness suite (`test_architecture_fitness.py` and `importlinter`) automatically validates these boundaries in continuous integration.
