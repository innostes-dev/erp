Innostes ERP is a modular enterprise resource planning platform engineered around **two lightweight execution engines** (`apps/web-app` for the user interface and `apps/api-server` for the backend ASGI runtime) and a decoupled **plug-in ecosystem**.

All domain capabilities—from multi-tenant identity and access management to commercial business applications (such as HRMS and CRM)—are authored as independent plug-ins. The engines contain no business logic of their own.

## 2. Visual Modelling (C4 Model)

Diagrams across this documentation follow the **C4 model for software architecture**, rendered as diffable, version-controlled Mermaid code using the `<Diagram>` component:

- **Level 1 (System Context)**: Shows how Innostes ERP sits in its enterprise environment, detailing interactions with human users (Admins, Staff, Auditors) and external systems (SMTP, Identity providers). Located in [Context and Scope](/docs/architecture/context-and-scope).
- **Level 2 (Containers)**: Highlights deployable execution units: the React 19 single-page application (`web-app`), the FastAPI backend service (`api-server`), and the PostgreSQL 16 database. Located in [Overview](/docs/architecture/overview).
- **Level 3 (Components)**: Breaks down the internal structure of `api-server` and `web-app`, detailing the module loader, session dependencies, routers, service layer, and ORM models. Located in [Kernel](/docs/architecture/kernel) and [Plug-ins](/docs/architecture/plugins).
- **Runtime Views**: Traces critical lifecycle workflows (token rotation, first-run setup, multi-tenant queries). Located in [First-run Setup](/docs/architecture/setup).

```bash

pnpm run arch-check

# Run diagram syntax checks, frontmatter validation, and ADR compliance gates
pnpm nx run landing:arch-docs-check
```
