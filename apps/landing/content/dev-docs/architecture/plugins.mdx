innostes ERP implements a modular, plug-in architecture where both the backend engine (`apps/api-server`) and the UI engine (`apps/web-app`) discover extensions dynamically at startup without importing them by name.

```text
 ┌────────────────────────────────────────────────────────┐
 │                      Backend Engine                     │
 │                     apps/api-server                    │
 └───────────────────────────▲────────────────────────────┘
                             │ discovers via entry-points
 ┌───────────────────────────┴────────────────────────────┐
 │                   innostes.modules                     │
 │   ┌───────────────┬───────────────┬────────────────┐   │
 │   │ kernel (core) │ hrms (domain) │ crm (domain)   │   │
 │   └───────────────┴───────────────┴────────────────┘   │
 └────────────────────────────────────────────────────────┘
```

## Backend Plug-ins

Backend plug-ins are standard Python packages that publish their `BaseModule` instance in the `innostes.modules` entry-point group in `pyproject.toml`:

```toml title="modules/hrms/backend/pyproject.toml"
[project.entry-points."innostes.modules"]
hrms = "hrms:module"
```

During startup lifespan initialization, `ModuleLoader` inspects installed entry points, mounts route collections, injects custom OpenAPI tags, and configures startup/shutdown lifecycle hooks:

```py title="apps/api-server/app/main.py"
loader = ModuleLoader(engine.registry)
loader.discover()
app = engine.create_app()
```

For the complete technical specification of module registration, lifecycle methods, and health check contracts, consult the canonical [Plug-in Contract](/docs/architecture/plugin-contract#the-basemodule-interface).

## Frontend Plug-ins

Frontend plug-ins are pnpm workspace packages consumed directly from source. Each package exports a declarative module or plugin manifest declaring routes, navigation links, and sub-features:

```ts title="apps/web-app/src/app/catalog.ts"
import { hrmsManifest } from '@innostes/hrms';
import { crmManifest } from '@innostes/crm';
import { apiLoggerManifest } from '@innostes/api-logger';

export const BUSINESS_MODULES_CATALOG = [hrmsManifest, crmManifest];
export const PLUGINS_CATALOG = [apiLoggerManifest];
```

The UI engine mounts navigation and route trees dynamically from this catalog, gating module visibility based on active tenant subscriptions.

For manifest interfaces, route definitions, and packaging standards, see [Frontend Contract](/docs/architecture/plugin-contract#2-frontend-plug-in-contract).
