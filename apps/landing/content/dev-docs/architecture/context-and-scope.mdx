The system context establishes the external boundaries of the Innostes ERP platform. It identifies the human personas who interact with the system, the external technical services it integrates with, and the communication protocols that link them.

## 2. Business Context Table

The table below describes the business responsibilities, inputs, and outputs for every persona and system boundary:

| Persona / System | Role & Responsibility | Business Inputs | Business Outputs |
|:---|:---|:---|:---|
| **Tenant Administrator** | Manages organisation settings, invites staff, assigns roles, and activates modules. | Tenant configuration, user invitations, role definitions, module activation flags. | Active organization workspace, RBAC assignments, audit records. |
| **Business Staff** | Executes day-to-day business operations in commercial modules (HRMS, CRM). | Leave requests, attendance entries, customer leads, sales opportunities. | Updated sales pipelines, approved leave records, customer correspondence. |
| **Platform Operator** | Deploys containers, monitors health probes, and manages database migrations. | Environment variables, release bundles, migration commands, backup schedules. | Operational service uptime, migrated schema revisions, health telemetry. |
| **External Integrator** | Connects third-party software (logistics, e-commerce, banking) via REST APIs. | HTTP REST requests with Bearer tokens or `X-API-Key` headers. | JSON data payloads, webhooks, paginated resource records. |
| **PostgreSQL Database** | Guarantees durable relational data persistence and transaction atomicity. | SQL DML/DDL queries, advisory lock acquire/release statements. | ACID query results, relational constraints, foreign key enforcement. |
| **SMTP Mail Server** | Delivers transactional emails to enterprise personnel. | RFC 5322 MIME messages, recipient email addresses, reset tokens. | Delivery receipts, bounce notifications. |

## 3. Technical Context & Protocols

Every interface crossing the platform boundary uses standardized, secure transport protocols:

| Interface | Protocol | Port | Authentication & Security | Payload Format |
|:---|:---|:---|:---|:---|
| **Browser Client → Web App** | HTTPS / HTTP/2 | `4200` (dev) / `443` (prod) | TLS 1.3, Content Security Policy | Static HTML, CSS, JavaScript chunks |
| **Web App → API Server** | HTTPS / REST | `8001` (dev) / `443` (prod) | Bearer JWT (`Authorization`), `X-Tenant-ID`, CORS origins whitelist | JSON (`application/json`) |
| **Integrator → API Server** | HTTPS / REST | `8001` (dev) / `443` (prod) | `X-API-Key` header with SHA-256 hash lookup | JSON (`application/json`) |
| **API Server → PostgreSQL** | TCP / PostgreSQL Wire Protocol | `5432` | Username, password (`SecretStr`), optional SSL/TLS (`prefer`/`require`) | Binary asyncpg SQL frames |
| **API Server → SMTP Server** | SMTP / TCP | `587` (STARTTLS) / `465` (SSL) | SMTP AUTH (Username / Password) | Plain text and HTML MIME messages |
| **CLI Tools → API Server** | Direct Execution / Local socket | N/A | Local operating system shell permissions, `.env` file credentials | Command arguments, stdout, exit codes |
