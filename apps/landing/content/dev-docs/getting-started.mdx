## Prerequisites

| Tool | Version | Check |
| --- | --- | --- |
| Node.js | 22 or newer | `node -v` |
| pnpm | 12 or newer | `pnpm -v` |
| Python | 3.12 or newer (only for `api-server`) | `python --version` |
| Git | any recent version | `git --version` |

<Callout title="Use pnpm only">
  The repo uses a pnpm workspace and `pnpm-lock.yaml`. Don't run `npm install` or `yarn` — they
  create a second lockfile and a different `node_modules` layout.
</Callout>

<Steps>
<Step>

### Install dependencies

From the repo root:

```bash
pnpm install
```

This installs packages for every app and package in the workspace.

</Step>
<Step>

### Set up the API (optional)

The API runs in its own Python virtual environment. Create it and install its packages, including
the kernel and every other backend plug-in, once:

```bash
pnpm nx run api-server:install
```

Copy `.env.example` to `.env` at the repository root and set your database connection
(`DATABASE_URL` or `DB_HOST`, `DB_USER`, …). `docker compose up db` starts a local Postgres.

</Step>
<Step>

### Run the apps

Each app runs on its own port:

| App | Command | URL |
| --- | --- | --- |
| landing (website + docs) | `pnpm nx dev landing` | http://localhost:3000 |
| web-app | `pnpm nx serve web-app` | http://localhost:4200 |
| api-server | `pnpm nx serve api-server` | http://localhost:8001 (API docs at `/docs`) |

To run the ERP locally (API + web-app together) use one command:

```bash
pnpm dev   # api-server on :8001 and web-app on :4200
```

<Callout type="warn" title="Port 4200 already used by another project?">
  If another dev server (e.g. an Angular app) also uses port 4200, `localhost:4200` may open that app
  instead. Open **http://127.0.0.1:4200**, or stop the other server.
</Callout>

Or use one terminal per app. web-app reads `@innostes/ui` and `@innostes/kernel` straight from their
source, so it starts in about a second, with nothing to build first, and edits to those packages
hot-reload. `pnpm nx dev landing` builds `@innostes/ui` first, so the website always uses the latest
components.

</Step>
<Step>

### Set the system up (first run only)

A fresh database has to be installed once. Until then the API answers `503 setup_required`, and
web-app shows the setup wizard. Either:

- **Web**: open web-app. The wizard asks for a **setup token**, printed in the api-server terminal
  ("FIRST-RUN SETUP REQUIRED"). You can also print it with `pnpm nx run kernel-backend:setup -- token`.
- **Command line**:
  ```bash
  pnpm nx run kernel-backend:setup -- install --name "Northwind Traders" --slug northwind
  ```

See [First-run Setup](/docs/architecture/setup) for details and how to reset it.

</Step>
<Step>

### Make your first change

Verify that hot reload and test pipelines work as expected:

1. Open `apps/web-app/src/app/App.tsx`.
2. Make a small text edit in a greeting or heading.
3. Observe instant hot module replacement in the running browser on http://localhost:4200.
4. Run the automated quality checks:
   ```bash
   pnpm nx run-many -t build typecheck
   ```
5. Revert your test edit once confirmed.

</Step>
<Step>

### Check your changes

Before opening a pull request, verify that all build, typecheck, and quality gates pass:

```bash
pnpm nx run-many -t build typecheck
pnpm run arch-check
pnpm nx run landing:docs-check
```

</Step>
</Steps>

## Useful commands

```bash
pnpm nx show projects          # list all projects
pnpm nx show project landing   # list a project's tasks
pnpm nx graph                  # open the dependency graph in the browser
pnpm nx affected -t build      # build only what your changes affect
pnpm nx reset                  # clear the Nx cache and daemon if things act strange
```
