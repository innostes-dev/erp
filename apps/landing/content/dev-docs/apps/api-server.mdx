`api-server` is the **backend engine**. It doesn't own any tables or business endpoints. It starts
FastAPI, finds every installed backend plug-in (the kernel, ERP modules), mounts their routes and
serves health checks and API docs. See [Architecture](/docs/architecture/overview).

## Setup

The API uses its own Python virtual environment in `apps/api-server/.venv`.

```bash
pnpm nx run api-server:install   # create .venv, install requirements.txt (includes the plug-ins)
pnpm nx serve api-server         # http://localhost:8001
```

Settings come from `.env` files (repository root or `apps/api-server/`) and environment variables.

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `8001` | Port the server listens on |
| `DATABASE_URL` | — | Postgres URL. Takes precedence over the `DB_*` variables |
| `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` | `localhost`, `5432`, `postgres`, `postgres`, `erp_dev` | Postgres connection |
| `AUTO_MIGRATE` | `false` | Apply kernel migrations on startup. Not needed for a fresh install: setup runs them |
| `CORS_ORIGINS` | `http://localhost:4200,http://127.0.0.1:4200` | Comma-separated browser origins allowed to call the API (the web-app URL) |
| `SETUP_ENABLED` | `true` | Allow first-run setup through the web wizard. Set `false` in production (command-line setup only) |
| `SETUP_TOKEN` | generated | One-time token for the web wizard. If unset, one is generated and printed in the log |
| `SETUP_TOKEN_FILE` | `kernel/backend/var/setup-token` | Where the generated token is kept until setup completes |
| `SETUP_ORG_NAME`, `SETUP_ORG_SLUG`, ... | | Used by `python -m kernel.setup install --from-env` |
| `JWT_SECRET_KEY` | dev value | Secret for signing tokens. **Always set in production** |
| `APP_ENV`, `APP_NAME`, `APP_VERSION`, `APP_DEBUG` | | Shown in `/` and the API docs |

## API docs

| URL | What |
| --- | --- |
| http://localhost:8001/docs | Swagger UI: browse and try endpoints |
| http://localhost:8001/redoc | ReDoc: readable reference |
| http://localhost:8001/openapi.json | Raw OpenAPI spec |

```bash
pnpm nx run api-server:openapi   # write apps/api-server/openapi.json without starting the server
```

## Endpoints

The engine's own endpoints. Everything else comes from plug-ins.

| Method | Path | Returns |
| --- | --- | --- |
| `GET` | `/` | Service name, environment, status and the loaded modules |
| `GET` | `/health` | API, database and per-module health. `200` if the database responds, `503` otherwise |

Currently loaded plug-ins:

| Module | Package | Category | Endpoints / Responsibilities |
| --- | --- | --- | --- |
| `setup` | `kernel` | Kernel | `/setup/status`, `/setup/checks`, `/setup`, plus the `setup_required` lock (see [Building Blocks](/docs/architecture/building-blocks)) |
| `tenancy` | `kernel` | Kernel | `/tenants`, `/tenants/{id}`, `/tenants/current/modules`, `/tenants/current/plugins` |
| `user` | `kernel` | Kernel | `/users`, `/users/{id}`, `/roles`, `/permissions` (IAM and RBAC) |
| `auth` | `kernel` | Kernel | `/auth/login`, `/auth/refresh`, `/auth/logout`, `/auth/api-keys`, `/auth/sessions` |
| `hrms` | `innostes-hrms` | Business | `/hrms/employees`, `/hrms/departments`, `/hrms/leaves` |
| `crm` | `innostes-crm` | Business | `/crm/leads`, `/crm/deals`, `/crm/contacts` |
| `api_logger` | `innostes-api-logger` | Extensible Plugin | `/api-logger/logs`, `/api-logger/stats` |

## How plug-ins are loaded

```py title="app/main.py"
engine = ServerEngine(settings=settings)
loader = ModuleLoader(engine.registry)
loader.discover()          # every package registered under "innostes.modules"
app = engine.create_app()
```

To add a plug-in, list it in `requirements.txt` and reinstall. Nothing in `app/` changes. See
[Plug-ins](/docs/architecture/plugins).

| Command | What it does |
| --- | --- |

| `pnpm nx serve api-server` | Dev server with reload on http://localhost:8001 |
| `pnpm nx test api-server` | Engine tests |
| `pnpm nx run api-server:openapi` | Export the OpenAPI spec |

## Adding a Python package

A package needed by a **plug-in** goes in that plug-in's `pyproject.toml` (`dependencies`). A package
needed by the **engine itself** goes in `apps/api-server/requirements.txt`. Then reinstall:

```bash
pnpm nx run api-server:install
```

## Docker

```bash
docker compose up --build    # Postgres + api-server on http://localhost:8001
```

The image installs the plug-ins from `kernel/backend` (and later module folders) the same way as local development.
